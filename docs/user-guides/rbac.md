# User Guide: RBAC

KubeMicroVM uses Kubernetes RBAC at several layers. This guide explains every
role in the system, who needs what permissions, and how to set it up.

> **Replace throughout this guide**:
> - `123456789012` → your AWS account ID (`aws sts get-caller-identity --query Account --output text`)
> - `my-cluster` → your EKS cluster name
> - `us-east-1` → your AWS region

---

## Overview

```
┌─────────────────────────────────────────────────────┐
│  IAM (AWS)                                           │
│  kube-microvm-operator role ──→ Lambda MicroVMs API  │
│  KubeMicroVMBuildRole       ──→ build MicroVM images │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│  Kubernetes RBAC                                     │
│  Operator SA ──→ CRD reconciliation                  │
│  Operator SA ──→ TokenReview + SubjectAccessReview   │
│  Operator SA ──→ Webhook validation (namespaces etc) │
│  App SA     ──→ microvms/token (per-VM, namespaced)  │
└─────────────────────────────────────────────────────┘
```

## 1. Operator IAM Role (AWS)

The operator pod assumes an AWS IAM role via EKS Pod Identity to call the
Lambda MicroVMs API. This role is created by the installer script or manually
via CloudFormation.

### Required permissions

```yaml
# Core MicroVM operations
- lambda:*Microvm*
- lambda:*NetworkConnector*
- lambda:*MicrovmImage*

# EC2 networking (for VPC connectors)
- ec2:DescribeSecurityGroups
- ec2:DescribeSubnets
- ec2:CreateNetworkInterface
- ec2:DescribeNetworkInterfaces
- ec2:DeleteNetworkInterface

# IAM
- iam:PassRole              # pass KubeMicroVMBuildRole + self (for network connectors)
- iam:CreateServiceLinkedRole   # for lambda.amazonaws.com

# STS
- sts:GetCallerIdentity
```

See [`iam/kube-microvm-operator-role.yaml`](../../iam/kube-microvm-operator-role.yaml)
for the complete CloudFormation template.

### Setup (EKS Pod Identity)

```bash
# 1. Create IAM role (CloudFormation)
aws cloudformation deploy \
  --stack-name kube-microvm-operator-role \
  --template-file iam/kube-microvm-operator-role.yaml \
  --capabilities CAPABILITY_IAM CAPABILITY_NAMED_IAM

# 2. Associate with the operator ServiceAccount
aws eks create-pod-identity-association \
  --cluster-name my-cluster \
  --namespace kube-microvm \
  --service-account kube-microvm-operator \
  --role-arn arn:aws:iam::123456789012:role/kube-microvm-operator
```

## 2. Build Role (AWS IAM)

The `KubeMicroVMBuildRole` is assumed by Lambda during image builds. It needs
access to read the S3 source zip.

```yaml
# Minimum permissions
- s3:GetObject        # read source zip
- s3:GetBucketLocation
- ecr:*               # push built image layers (if using ECR base)
```

Reference in `MicroVMImage`:

```yaml
spec:
  buildRoleArn: "arn:aws:iam::123456789012:role/KubeMicroVMBuildRole"
```

## 3. Operator Kubernetes RBAC

The operator `ServiceAccount` (`kube-microvm-operator` in `kube-microvm` namespace)
needs several ClusterRoles, all created automatically by the Helm chart.

### CRD reconciliation roles

Auto-generated by JOSDK — one ClusterRole per reconciler:

| ClusterRole | Permissions |
|-------------|-------------|
| `microvmreconciler-cluster-role` | CRUD on `microvms` + status |
| `microvmimagereconciler-cluster-role` | CRUD on `microvmimages` + status |
| `microvmnetwork-reconciler-cluster-role` | CRUD on `microvmnetworks` + status |
| `microvmreplicaset-reconciler-cluster-role` | CRUD on `microvmreplicasets` + status |
| `microvmpoolreconciler-cluster-role` | CRUD on `microvmpools` + status |

### Token endpoint RBAC

Required for the operator to validate in-cluster token requests:

```yaml
# ClusterRole: kube-microvm-operator-token-auth-role
rules:
- apiGroups: ["authentication.k8s.io"]
  resources: ["tokenreviews"]
  verbs: ["create"]
- apiGroups: ["authorization.k8s.io"]
  resources: ["subjectaccessreviews"]
  verbs: ["create"]
```

### Webhook validation RBAC

Required for the validating webhook to check namespace labels and quotas:

```yaml
# ClusterRole: kube-microvm-operator-webhook-role
rules:
- apiGroups: [""]
  resources: ["namespaces"]
  verbs: ["get"]
- apiGroups: [""]
  resources: ["resourcequotas"]
  verbs: ["list"]
- apiGroups: ["lambda.aws.amazon.com"]
  resources: ["microvmclasses"]
  verbs: ["get"]
```

All operator RBAC is installed automatically by `helm install kube-microvm-operator`.

## 4. App Pod RBAC (token access)

Pods that need to call MicroVM endpoints must have a `ServiceAccount` with
permission to `create` on `microvms/token`.

This is **namespaced** (not cluster-wide) and scoped to specific VMs via `resourceNames`.

### Setup

```yaml
# ServiceAccount for your application pod
apiVersion: v1
kind: ServiceAccount
metadata:
  name: my-app-sa
  namespace: default
---
# Role — scoped to specific VM in this namespace
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: microvm-token-my-vm
  namespace: default
rules:
- apiGroups: ["lambda.aws.amazon.com"]
  resources: ["microvms/token"]
  verbs: ["create"]
  resourceNames: ["my-vm"]     # limit to this VM only
---
# Bind the Role to the app SA
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: my-app-sa-can-get-token
  namespace: default
subjects:
- kind: ServiceAccount
  name: my-app-sa
  namespace: default
roleRef:
  kind: Role
  name: microvm-token-my-vm
  apiGroup: rbac.authorization.k8s.io
```

### Multi-VM access

Grant access to multiple VMs in one Role:

```yaml
resourceNames: ["vm-a", "vm-b", "vm-c"]
```

### Verifying access

```bash
# Without resourceNames (broad Role):
kubectl auth can-i create microvms --subresource=token \
  --as=system:serviceaccount:default:my-app-sa \
  -n default
# yes

# Note: with resourceNames in the Role, `can-i` returns "no" because
# it cannot evaluate name-specific constraints. The operator still
# authorises correctly at runtime via SubjectAccessReview.
```

## 5. `microvm-token-requester` ClusterRole

A pre-installed ClusterRole that grants `create` on `microvms/token` across
all resource names in any namespace. Use this for broad access:

```yaml
# ClusterRoleBinding — grants my-app-sa access to ALL VMs in ALL namespaces
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: my-app-sa-global-token
subjects:
- kind: ServiceAccount
  name: my-app-sa
  namespace: default
roleRef:
  kind: ClusterRole
  name: microvm-token-requester
  apiGroup: rbac.authorization.k8s.io
```

> ⚠️ Use `microvm-token-requester` only for admin or tooling SAs. For application
> pods, use a namespaced `Role` with `resourceNames` instead.

## 6. Namespace Permission

The validating webhook requires a namespace to have the label:

```
lambda.aws.amazon.com/manage-microvms=true
```

Without this label, `MicroVM` creates are rejected. The `default` namespace is
labelled automatically at install time.

```bash
# Enable a namespace
kubectl label namespace my-team lambda.aws.amazon.com/manage-microvms=true

# Disable (removes operator watching + webhook enforcement)
kubectl label namespace my-team lambda.aws.amazon.com/manage-microvms-
```

## Summary

| Who | Needs | How |
|-----|-------|-----|
| Operator pod | AWS Lambda MicroVMs API | IAM role + EKS Pod Identity |
| Operator pod | k8s CRD reconciliation | Auto-installed ClusterRoles via Helm |
| Operator pod | TokenReview + SAR | `kube-microvm-operator-token-auth-role` |
| Operator pod | Namespace/quota checks | `kube-microvm-operator-webhook-role` |
| App pod | Call one specific VM | Namespaced `Role` with `resourceNames` |
| Admin tool | Call any VM | `microvm-token-requester` ClusterRole |
| Lambda | Build MicroVM images | `KubeMicroVMBuildRole` IAM role |
